01 System Overview

Clarity
at altitude.

Aviation-grade design tokens and UI components. Colors carry semantic meaning — never decoration. Every hue has one assigned role.

PRINCIPLES
→Color encodes status, never style
→Hierarchy via contrast, not scale
→Density is intentional, never accidental
→Designed for long viewing sessions

07 Usage Guidelines
✓ DO
Use WARNING strictly for critical conditions requiring immediate action
Pair color with text — never rely on color alone to convey meaning
Keep all numeric readouts in B612 Mono at all times
Show most critical status at top of any list
✗ DON'T
Don't use semantic colors (green/amber/red) decoratively
Don't add gradients or shadows to data panels
Don't clutter — one panel, one topic
Don't use NOMINAL green as a brand or accent color
◈ PALETTE CHOICE
Standard — aviation-traditional, default for most apps
Colorblind Safe — required when accessibility is a strict constraint
Soft — operator desks, 8h+ sessions, fatigue reduction

FOCUS INDICATORS — 2.4.7
All interactive elements use *:focus-visible — 2px cyan outline, visible to keyboard and assistive technology users. outline:none is never applied globally.
FOCUSED ELEMENT
EXEMPTIONS — 1.4.3
--col-muted and disabled states are fully exempt — inactive UI components have no contrast requirement
--col-target and --col-warning pass AA for normal text; large text (≥ 18pt) only needs 3:1
Logotypes and purely decorative elements are exempt
TOUCH TARGETS — 2.5.8
WCAG 2.2 AA minimum: 24×24px for all interactive controls
Recommended: min-height:44px for primary action buttons on mobile
Always pair color with a visible text label — color is never the sole conveyor of meaning
